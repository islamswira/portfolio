From UINavigationController to NavigationStack: Modern Navigation in SwiftUI

For years, UINavigationController was the default way to handle navigation in iOS apps. With SwiftUI, NavigationStack and NavigationPath give us a data-driven alternative. In this article, we’ll walk through the mental shift from “push/pop view controllers” to describing navigation as state.

UIKit → SwiftUI

From imperative stacks to data-driven navigation

In UIKit you call pushViewController and popViewController directly on a shared UINavigationController. In SwiftUI, your navigation stack is just data – an array or a NavigationPath – and the framework keeps the UI in sync with that state.

  • UIKit: “Go to this screen now.”
  • SwiftUI: “Here is the path I want.”
  • Result: easier deep links, testing, and state restoration.
UIKit stack
pushViewController(_:animated:)
NavigationStack
NavigationLink(value:)

Same flow, different mindset: from pushing controllers to evolving a path that describes where you are.

Why migrate your navigation?

For a long time, navigation in UIKit worked well enough. But as apps grew, logic around UINavigationController often became a tangle of push / pop calls, conditional transitions and cross-feature deep links.

SwiftUI’s NavigationStack gives you a chance to simplify. Instead of sprinkling navigation calls across view controllers, you treat the navigation state as data that lives next to the rest of your app state.

How navigation worked in UIKit

In UIKit, you typically store a reference to the navigation controller and call methods on it: 


// UIKit style navigation

class ArticlesViewController: UIViewController {

    func didSelectArticle(_ article: Article) {
        let detailVC = ArticleDetailViewController(article: article)
        navigationController?.pushViewController(detailVC, animated: true)
    }

    func didFinish() {
        navigationController?.popViewController(animated: true)
    }
}

This works, but navigation logic tends to be spread out:

  • Each view controller can decide where to navigate next.
  • Deep links require custom coordinators or router objects.
  • Restoring the stack after relaunch is non-trivial.

Enter NavigationStack

In SwiftUI, the primary navigation container is NavigationStack. It owns a path – usually an array or NavigationPath – which represents the current stack of destinations. 


struct ArticlesView: View {
    @State private var path: [Article] = []

    var body: some View {
        NavigationStack(path: $path) {
            List(articles) { article in
                NavigationLink(value: article) {
                    ArticleRow(article: article)
                }
            }
            .navigationDestination(for: Article.self) { article in
                ArticleDetailView(article: article)
            }
            .navigationTitle("Articles")
        }
    }
}

The visible stack is now just an array of Article. To open a detail screen, you append an article to the path. To go back, you remove the last element.

Mapping UIKit APIs to SwiftUI patterns

1. Pushing a detail screen


// UIKit
navigationController?.pushViewController(detailVC, animated: true)


// SwiftUI
NavigationLink(value: article) {
    ArticleRow(article: article)
}

In SwiftUI you don’t push imperatively. You describe a link that, when activated, appends to the navigation path.

2. Programmatic navigation


// UIKit
func openArticle(_ article: Article) {
    let detailVC = ArticleDetailViewController(article: article)
    navigationController?.pushViewController(detailVC, animated: true)
}


// SwiftUI
func openArticle(_ article: Article) {
    path.append(article)
}

Programmatic navigation becomes a simple state mutation on path.

3. Going back


// UIKit
navigationController?.popViewController(animated: true)


// SwiftUI
path.removeLast()
// or reset:
path = []

Back navigation is no longer a method call on a controller. It is a change in your navigation state.

Deep linking with NavigationPath

One of the biggest differences from UIKit is how deep links are handled. Because the stack is just data, you can construct it directly from a URL or routing configuration. 


enum Route: Hashable {
    case list
    case article(id: UUID)
}

struct RootView: View {
    @State private var path = NavigationPath()

    var body: some View {
        NavigationStack(path: $path) {
            ArticlesView()
                .navigationDestination(for: Route.self) { route in
                    switch route {
                    case .list:
                        ArticlesView()
                    case .article(let id):
                        ArticleDetailView(id: id)
                    }
                }
        }
        .onOpenURL { url in
            if let route = route(from: url) {
                path.append(route)
            }
        }
    }
}

In UIKit this usually requires a custom coordinator that parses the URL and manually pushes the right view controllers. With NavigationPath you can rebuild the stack from pure data.

Coexisting with UIKit during migration

Real projects rarely switch from UIKit to SwiftUI in one step. You can embed SwiftUI screens inside a UIKit navigation controller or present UIKit flows from SwiftUI using representable wrappers. 


// Embedding SwiftUI inside UIKit
let rootView = ArticlesView()
let hosting = UIHostingController(rootView: rootView)
let navigationController = UINavigationController(rootViewController: hosting)
window.rootViewController = navigationController


// Embedding UIKit inside SwiftUI
struct LegacyProfileView: UIViewControllerRepresentable {
    func makeUIViewController(context: Context) -> UIViewController {
        LegacyProfileViewController()
    }

    func updateUIViewController(_ vc: UIViewController, context: Context) {}
}

This hybrid approach lets you migrate feature by feature while keeping the app stable.

Summary

Moving from UINavigationController to NavigationStack is more than a syntax change. It’s a shift from imperative navigation calls to describing your navigation state as data.

  • UIKit: navigation lives in view controllers.
  • SwiftUI: navigation lives in values and paths.
  • Deep links: easier to support by constructing the path directly.
  • Migration: wrap SwiftUI in UIKit and UIKit in SwiftUI to move flow by flow.
