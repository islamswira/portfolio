From AppDelegate & SceneDelegate to SwiftUI’s @main App

UIKit apps start in AppDelegate and SceneDelegate. SwiftUI introduces a new lifecycle with a declarative entry point: the @main App type. In this article we compare the two models and show how to migrate gradually without breaking your existing flow.

Lifecycle Evolution

The shift from imperative delegates to a declarative app structure

UIKit splits responsibilities between AppDelegate and SceneDelegate. SwiftUI unifies everything under a single @main App entry point with cleaner lifecycle handling, multi-window support, and scene-based state management.

  • UIKit: scattered callbacks.
  • SwiftUI: one clean entry point.
  • Migration: painless using @UIApplicationDelegateAdaptor.

How the lifecycle worked in UIKit

UIKit apps historically started with AppDelegate handling global events like launching, notifications and background transitions. From iOS 13, SceneDelegate was introduced to manage windows and scenes. 


@UIApplicationMain
class AppDelegate: UIResponder, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions options: ...
    ) -> Bool {
        FirebaseApp.configure()
        return true
    }
}


class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?

    func scene(_ scene: UIScene, willConnectTo session: UISceneSession, ...) {
        window = UIWindow(windowScene: scene as! UIWindowScene)
        window?.rootViewController = UIHostingController(rootView: RootView())
        window?.makeKeyAndVisible()
    }
}

Enter SwiftUI’s @main App


@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            RootView()
        }
    }
}

This replaces both AppDelegate and SceneDelegate. Your app’s window, main view, and scene structure are now declared inside a single SwiftUI type.

Lifecycle handling with scenePhase


@Environment(\.scenePhase) private var scenePhase

var body: some Scene {
    WindowGroup {
        RootView()
            .onChange(of: scenePhase) { phase in
                switch phase {
                case .active: startSession()
                case .background: saveState()
                default: break
                }
            }
    }
}

Keeping AppDelegate during migration

Many real-world apps still require AppDelegate logic (Firebase, push notifications, background tasks). SwiftUI supports this natively using: 


class AppDelegate: NSObject, UIApplicationDelegate {
    func application(_ application: UIApplication,
                     didRegisterForRemoteNotificationsWithDeviceToken token: Data) {
        PushManager.shared.updateToken(token)
    }
}

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var delegate

    var body: some Scene {
        WindowGroup { RootView() }
    }
}

Advanced migration notes for production apps

Migrating to SwiftUI’s @main App lifecycle is more than replacing two files. Real-world apps rely on deep linking, background tasks, multi-window behavior and platform-specific events. The SwiftUI lifecycle can handle all of these—but you need to understand how the new system maps to UIKit's behavior.

1. SwiftUI’s multi-scene system replaces SceneDelegate entirely

Unlike UIKit’s SceneDelegate, SwiftUI’s scene system is declarative. Each scene is defined as a value in your App body. You can add multiple windows, customize activation, and route external events to specific scenes. 


var body: some Scene {
    WindowGroup("Dashboard") { DashboardView() }
        .handlesExternalEvents(matching: ["dashboard"])

    WindowGroup("Inspector") { InspectorView() }
        .handlesExternalEvents(matching: ["inspector"])
}

2. State restoration using @SceneStorage, @AppStorage and NavigationPath

UIKit relied on encodeRestorableState and application(_:shouldRestoreState). SwiftUI performs automatic state restoration using @SceneStorage and @AppStorage, and can restore navigation stacks using a Codable NavigationPath. 


@SceneStorage("selectedTab") private var selectedTab = 0

3. The SwiftUI App struct lives for the entire lifetime of the process

A common misconception is that SwiftUI recreates the App struct the way it recreates Views. It does not. The App struct is initialized once at launch and persists until termination, even though its body is recomputed. Initialization logic inside init() is guaranteed to run exactly once.

4. The environment replaces major UIApplication callbacks

Many responsibilities of UIApplicationDelegate move to SwiftUI environment values: 


@Environment(\.openURL) private var openURL
@Environment(\.scenePhase) private var scenePhase
@Environment(\.dismiss) private var dismiss

These remove the need for several AppDelegate callbacks, routing them declaratively instead.

5. SwiftUI lifecycle unifies iOS, macOS and iPadOS behavior

SwiftUI’s lifecycle is cross-platform. This enables features like:

  • customizing macOS menu commands
  • supporting multiple windows on iPad/mac
  • adding custom keyboard shortcuts

var body: some Scene {
    WindowGroup { RootView() }
        .commands {
            SidebarCommands()
            CommandMenu("Developer") {
                Button("Reload Data") { reload() }
            }
        }
}

6. Handling background tasks in the SwiftUI App lifecycle

UIKit apps typically register background tasks inside AppDelegate. In SwiftUI, perform this in init() of your App struct: 


@main
struct MyApp: App {
    init() {
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "sync",
            using: nil
        ) { task in
            handleBackgroundSync(task: task as! BGProcessingTask)
        }
    }
}

7. Handling notifications inside SwiftUI views

Instead of relying on delegate callbacks, you can respond to notifications directly from your SwiftUI Views: 


.onReceive(NotificationCenter.default.publisher(for: .userLoggedOut)) { _ in
    navigationPath = []
}

8. You can still use a custom SceneDelegate if needed

Rare but useful for large UIKit projects during migration: 


@SceneDelegateAdaptor(CustomSceneDelegate.self) var sceneDelegate

9. SwiftData integrates directly at the lifecycle level


WindowGroup {
    RootView()
        .modelContainer(for: [UserModel.self])
}

This is now the preferred persistence model for SwiftUI apps.

10. Use init() in your App type for global setup

This replaces most of the logic that previously lived in AppDelegate: 


@main
struct MyApp: App {
    init() {
        FirebaseApp.configure()
        Analytics.shared.start()
        DependencyContainer.shared.bootstrap()
    }
}

Summary

  • UIKit: lifecycle split across AppDelegate + SceneDelegate.
  • SwiftUI: unified @main App entry point.
  • scenePhase: replaces major lifecycle callbacks.
  • AppDelegateAdaptor: keeps legacy logic during migration.
